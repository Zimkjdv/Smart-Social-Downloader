# P1 可靠性、保存與診斷

更新日期：2026-10-11。實作進度及尚未驗證的環境見 [ROADMAP.md](../ROADMAP.md)。

## 1．停止下載與無進度逾時（R06）

一般媒體與 X 帳號都提供停止圖示。每個工作在獨立 Python 程序執行，Windows Job Object 管理該程序及其啟動的合併工具；停止會結束這組程序，後續佇列繼續。不會搜尋或終止使用者另外開啟的 Chrome／FFmpeg。

- **暫停**：阻止後續工作／帳號貼文開始，目前正在處理的內容繼續。
- **停止**：結束目前工作，保留已保存檔案及部分下載檔；狀態顯示「已停止」，由使用者按重新下載／同步。
- **無進度逾時**：設定 → 一般設定 → 安全佇列，預設 **300 秒**，可設 **30～3600 秒**，儲存後供下一個工作使用。它不是整個影片的最長下載時間。
- 收到媒體資料、進度變更或合併期間有 CPU 活動會更新進度時間；長影片只要持續處理就不因總耗時被停止。平台等待、Rate、冷卻及手動暫停的排程等待不計入無進度時間。
- 程序異常退出、通訊異常或無進度逾時保留明確錯誤；排程器另有恢復流程及健康狀態，避免單一工作失敗後無法開始下一項。
- 大型檔案清單以分段匿名管線傳送；單 frame 保持 16 MiB 上限，UTF-8 重組訊息最多 64 MiB。超限顯示明確容量錯誤，錯序／截斷顯示通訊錯誤；停止或失敗後仍處理下一項。這不是無限容量保證，大帳號的序列化／保存成本仍待量測。
- 網頁重新整理不影響後端。正常關閉後端時中斷的工作重新排隊；使用者已要求停止的工作不自動恢復。強制終止或斷電只能恢復到最後成功保存的狀態。

設定中的「本機紀錄與下載程序」顯示 worker 是否可用及最近的進度等待時間。登入資料透過匿名管線交給子程序，不放進命令列參數、程序日誌或診斷報告。

## 2．通用媒體保存紀錄（R08）

一般下載使用 `data/media-manifest.sqlite3`，以**來源識別＋下載根目錄**區分。來源以 SHA-256 指紋作索引，逐檔保存相對路徑、大小、修改時間、引擎及媒體 ID；只有所有完成檔案仍符合紀錄時才略過來源取得。

- YouTube 的 watch／shorts／live／youtu.be 同影片 ID 使用相同識別；X 單篇仍使用貼文 ID。
- 一般網址保留 query，避免把不同媒體 ID、畫質或簽章當成同一內容。
- 搬移、改名、刪除、大小或修改時間改變，以及更換下載根目錄，都重新取得。工具不搜尋搬走的副本。
- 舊成功列只有來源、路徑及合計大小：首次核對相符後可匯入，再建立逐檔紀錄；沒有可信成功紀錄時不只憑同名檔案略過。
- 僅單檔且引擎、穩定媒體 ID、副檔名一致時，來源標題改變仍可補回原記錄路徑。相簿不憑檔案順序猜測身份；媒體集合／格式改變可能使用新路徑。
- manifest 不可讀時重新取得並提醒；保存紀錄失敗不把檔案說成遺失，但下次可能再下載。
- X 帳號仍須掃描目前可存取清單，沿用逐篇／逐檔核對與補抓；不因整個帳號曾成功就略過新媒體。

這不是內容雜湊去重或來源內容監控。原檔 metadata 未改變時不會再次詢問平台是否更新內容；需要取得新版時按重新下載。詳見 [去重政策](DOWNLOAD_DEDUP.md)。

## 3．版本、備份與恢復（R09）

`data/state.json` 現在包含 `schema_version: 2`。舊版 schema 0／1 紀錄通過驗證後遷移；先完整驗證清單再載入，不部分套用損壞內容。中斷工作、額度及冷卻的恢復結果會重新保存。

保存流程：驗證 → 暫存檔寫入／flush／fsync → 原檔替換。覆寫前，現有有效紀錄保存為 `data/state.json.bak`；損壞主檔不會覆蓋有效備份，另存 `data/state.corrupt-時間.json`。

- 主檔缺失或損壞且備份有效：自動恢復並在設定中提示。
- 恢復先完整驗證、重建候選工作、佇列、設定與冷卻，再一次套用；URL 只驗證語法，不因離線／DNS 暫時失敗就丟掉歷史。主檔正規化失敗也會嘗試有效備份，不留下半份工作。
- 沒有有效主檔或備份：保留原輸入並提示，阻止後續自動保存覆寫；請修復紀錄或還原有效備份後重新啟動。重新保存按鈕不能取代損壞歷史修復，不能承諾找回尚未保存的工作。
- 保存失敗：設定顯示錯誤；目前變更只在記憶體中。修正空間或權限後按「重新保存紀錄」，確認成功再關閉服務。
- 主檔或備份來自較新 schema：保留兩者並阻止覆寫，需改用相容版本。主檔缺失／損壞或未先載入時也保護新版備份，不能用重新保存按鈕強行降版。

備份包含私人下載清單及路徑，與 `data/` 一起排除 Git／發布包。這是本機恢復備份，不是跨磁碟備份；磁碟損壞、斷電及多個服務共寫同一資料夾不在成功保證內。

API 狀態快照附帶服務實例 ID 與遞增序號。較早輪詢若較晚返回，介面不會用它覆蓋已呈現的新快照；服務重啟會產生新實例 ID。這些是記憶體中的回應排序欄位，不作為登入憑證，也不保存到歷史紀錄。

## 本機 HTTP 輸入與資源限制（N03～N05）

- **Cookie 連接**：入口僅接受 1～12 筆物件；domain／name／value 必須是非空字串，分別最多 253／128／8192 字元，不接受控制字元。expires 可省略（視為 session Cookie），提供時須是非負、有限的 Unix 秒數，最多至西元 9999 年末；不接受 boolean／null。未知 Cookie 名稱或非 X 網域不會當成 X 登入使用。格式錯誤回覆 400，不回顯 Cookie 值、不替換既有登入、不消耗有效配對票證；修正資料後可重試或重新配對。配對票證亦先驗證 ASCII／長度，再進行安全比較。
- **暫停 API**：`POST /api/pause` 只接受 `{"paused":true}`／`{"paused":false}`。缺少 paused、字串（含 `"false"`）、數字、null、陣列與物件均回覆 400，不修改或保存佇列。介面原本即傳送 boolean。
- **讀取期限**：標頭與 body 從 handler 開始讀取起共用 **10 秒絕對期限**；持續零碎送資料不會延長期限。標頭不完整時關閉連線；body 逾時且客戶端仍可接收時回覆 **408**。提早 EOF 回覆 400；客戶端中斷則回收連線。
- **body 格式**：POST 要有唯一的十進位 Content-Length，大小 1～100,000 bytes；重複／非數字／超限長度及 Transfer-Encoding 被拒絕。服務不支援 chunked request body。JSON 必須是物件，無效 UTF-8、過深結構、NaN／Infinity 均得到不包含原始輸入的 400。
- **併發與回應**：最多 **32 條 active HTTP 連線**，包含讀取、路由處理及回應；超量在建立 handler 執行緒前回覆 **503** 與 `Retry-After: 1`，不執行 API 操作。每條連線處理一個請求，socket 寫入期限 **5 秒**。shutdown 只關閉此服務接受的 socket，HTTP 斷線不會停止背景下載。這些為固定伺服器常數，沒有新增使用者設定。

主介面的 15 秒期限及 Chrome 連接器的 12 秒期限仍保留；未確認的寫入不自動重送。這些限制處理 HTTP 傳輸與併發，不限制下載總時間，也不能中斷路由內的磁碟或其他應用程式操作；保存鎖成本仍待 N07 量測。Host／Origin／連接器配對政策不變，服務仍限 loopback。

## 4．媒體網路目標（R11）

下載子程序只允許**公開 HTTP／HTTPS** 目標。DNS 回答中有非公開位址就拒絕；socket 連線使用已核對的數字位址，避免 DNS 預查和連線之間改成未核對的目標。重新導向、播放器 manifest、HLS 金鑰／片段及 DASH 初始化／音訊／片段沿用相同政策。[Python socket 說明](https://docs.python.org/3/library/socket.html)

這與本機 API 的來源檢查不同：正常使用介面的 `127.0.0.1` 連線被允許，**作為待下載媒體來源的回環／內網位址被拒絕**。一般 YouTube、X 與公開媒體網址仍依解析器支援程度處理。

為維持此傳輸政策：

- yt-dlp 使用 Python Urllib transport；不使用自行解析 DNS 的 curl transport 或瀏覽器 impersonation。
- 媒體下載不使用系統 HTTP proxy，避免 proxy 成為未檢查的傳輸路徑。
- 原生 HLS／DASH 下載可以使用，FFmpeg 仍可合併本機影音。
- 需要外部 FFmpeg 網路下載、RTMP 或其他外部網路下載器的來源會提示不支援，不回退到未檢查的路徑。[yt-dlp downloader dispatch](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/downloader/__init__.py)
- 子程序中的 patch 不套用到本機 HTTP 服務，因此不阻止瀏覽器讀取工具 API。

這是應用程式 HTTP 傳輸檢查，**不是作業系統沙箱**。不能對任意第三方程式碼或未來新增傳輸器宣稱網路隔離；更新引擎時須重新跑回歸測試。

## 5．遮蔽與診斷匯出（R12）

錯誤／提醒寫入紀錄、API、終端機與匯出前共用遮蔽器：移除 Cookie、Authorization、已知 Token／密碼鍵值、URL 使用者密碼、query／fragment 及本機私人路徑。

設定 →「診斷」→「匯出診斷」下載 `ssdl-diagnostics.json`，只包含環境、保存／worker／Rate 狀態、工作 ID／平台／狀態及已遮蔽錯誤，不包含媒體網址、標題、檔案清單、下載資料夾或實際登入資料；不會自動傳送給別人。檔案控制仍保留操作所需路徑，不能把整份 `/api/state` 當成分享報告。

遮蔽依已知格式處理，不能辨識任意未標示的秘密；分享前仍可自行查看報告。測試只使用合成敏感值。
