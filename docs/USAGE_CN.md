# 操作指南

[繁體中文首頁](../README_CN.md) | [English usage guide](USAGE.md)

此處保留詳細安裝與操作說明。指令中的路徑皆以專案根目錄為基準；應用程式版本及發布步驟見 [維護指南](MAINTENANCE.md)。

## 核心功能

以下功能已實作：

| 功能 | 目前行為 |
| --- | --- |
| 多平台連結解析下載 | 支援單個或多個影片、圖片與貼文網址，自動排隊解析及背景下載；實際平台支援取決於下載引擎及內容權限。 |
| 通用網頁媒體解析後備 | yt-dlp 回報 Unsupported URL 時，自動檢查 HTML5 影音來源、媒體資訊、播放器 JSON 及嵌入頁面，再交給 yt-dlp 下載；沿用來源頁面的平台資料夾。 |
| 平台資料夾 | 影片、社群媒體與圖片直連都按平台分資料夾，例如 `youtube`、`twitter`、`instagram`、`tiktok`；保留解析器原有的帳號／相簿子資料夾。 |
| 多網址輸入 | 每行一個，或以空格、逗號分隔；一次最多 30 個，清單最多 200 個項目。 |
| 影片畫質下拉選單 | 預設最高畫質，可選 2160p～144p 上限；自動選擇最高且不超過上限的來源版本，重新下載沿用工作設定，圖片不縮放。X 帳號同步維持最高畫質。 |
| X 帳號媒體模式 | 支援 X 帳號首頁、媒體頁或 @帳號；逐篇下載此帳號發布的圖片與影片，保留原尺寸／最高可用版本，並可停止、繼續同步及補抓新增媒體。 |
| X 媒體總數預掃描 | 先掃描本次可存取的媒體清單，顯示總檔案數、需要下載及已存在數量，再下載；掃描中顯示已找到數量，掃描完成後提供檔案數進度。 |
| Add to Download Queue／加入下載佇列 | 所有新工作及重新下載均套用同一組延時與限流規則。 |
| Delay 3s – 8s jitter | 上一項工作結束後，隨機等待 3～8 秒才開始下一項；服務首次處理工作時也會先等待。 |
| 主動請求節流 | 下載工具共用 HTTP 請求節流器，新請求的開始時間至少間隔 1 秒，涵蓋 yt-dlp、gallery-dl 及圖片直連的 Python HTTP 呼叫。 |
| 每小時工作上限／Rate | 預設最近 60 分鐘最多啟動 40 個工作，可在右上角設定改為 1～1000；達上限後等待名額釋出。 |
| 重設 Rate／Reset Rate | 點擊頂部 Rate 區塊或設定的重設按鈕，先顯示確認彈窗；確認後清除已用工作計數，立即生效並保存。後續啟動的工作重新累計，每小時上限、工作延時及平台冷卻保留。 |
| 頂部容量與檔案數 | 顯示目前下載資料夾的實際媒體容量及檔案數，點擊可在 Windows 開啟資料夾。 |
| 頂部 Pause／Resume 與設定 | 可直接暫停或繼續後續工作，與清單按鈕同步；齒輪入口可修改下載位置、工作上限及 X 登入方式。 |
| 更新狀態與自動更新 | 頂部圓形箭頭按鈕可立即更新本機下載狀態；閒置時預設每 30 秒，有等待中／執行中工作時每 2 秒更新進度，保留輸入與設定草稿。 |
| 繁中／English 介面切換 | 右上角地球圖示旁的 EN／繁中按鈕立即切換語言；主畫面、設定、狀態、操作說明與 Chrome 連接頁提供英文，語言選擇保存於目前瀏覽器。 |
| 設定分頁 | 分為一般設定、X 登入與診斷；頂部導覽及底部操作固定顯示，切換分頁保留未儲存的輸入。 |
| Sequential Mode | 1 個下載 worker，逐項處理；影片片段也設定為單一並行下載。 |
| Active Queue Monitor／即時佇列監控 | 顯示目前工作與進度，以及等待中、下載中、已完成、失敗的數量；清單可依狀態、平台及關鍵字篩選。 |
| 清單分頁與捲動 | 後端先篩選再分頁，預設 20 個工作，可選 10／20／50；傳送目前頁面與全域統計，檔案／診斷明細按需讀取。保留固定表頭、捲動及頁碼；每頁筆數保存於瀏覽器。 |
| 減少重畫與快取回收 | 保留未變動資料列／欄位及縮圖，容量增量更新；提供容量重掃與縮圖清理。預覽快取預算 128 MiB／1000 個，30 天未使用回收。 |
| SIZE / TIME | 顯示檔案容量與下載耗時；多檔項目完成後加總容量，下載中顯示當前媒體容量、已用時間及引擎提供的剩餘時間。 |
| 狀態圖示徽章 | 等待使用時鐘、下載中使用旋轉圖示、完成使用勾選圓圈、失敗使用驚嘆號，並顯示目前介面語言的狀態文字。 |
| 下載提醒 | 狀態右側以小型警告圖示與數量顯示；滑鼠移上可查看提示，點擊開啟完整提醒內容。與狀態徽章保持相同高度，提供中英文說明及鍵盤操作。 |
| ACTION 圖示操作 | 播放／查看、開啟所在資料夾、重新下載、移除紀錄，以及所有下載中的停止圖示，固定同一排。滑鼠移上顯示說明，多檔項目先選擇檔案。 |
| 本機媒體縮圖 | 圖片生成小尺寸預覽，影片擷取一幀；多檔項目顯示第一個可預覽媒體與數量角標，點擊可播放／查看，無法生成時保留媒體圖示。 |
| Queue Ready／Idle 狀態列 | 頂部顯示閒置、準備下載、安全延時倒數、下載中、暫停、限流冷卻或服務未連線；右側顯示延時與單 worker 設定。 |
| 清除已完成／清除全部 | 一鍵清理下載清單，保留已下載檔案；清除全部也會移除尚未開始的工作。 |
| 重新下載／重試失敗 | 個別項目可重新下載，也可一次將全部失敗項目排回安全佇列。 |
| 環境診斷 | 設定內顯示 Python、下載引擎、FFmpeg、JavaScript runtime、套件相依性、Chrome、登入加密及連接埠，提供修復方式。 |
| API 逾時與資料保留 | 請求期限 15 秒，檢查 JSON 與必要欄位；更新失敗保留上次有效清單，按鈕恢復，輪詢繼續。 |

## 啟動

1. 安裝 Python 3.12；安裝與 CI 均以此版本為基準。
2. 第一次雙擊 `setup.bat`，建立專屬環境並安裝已鎖定版本的下載引擎；之後使用 `start.bat` 啟動。直接執行 start 時，未完成安裝也會先呼叫 setup。
3. 在瀏覽器開啟 `http://127.0.0.1:8765`。

也可以在終端機執行 `python tools/manage.py setup`，再執行 `.venv\Scripts\python.exe tools/manage.py start`。後續啟動只檢查本機環境，包含 `pip check`，不安裝或更新套件。完整流程見 [安裝說明](RELEASE.md)。目前以 Windows 為主要支援環境。

### 環境診斷及狀態更新

設定 →「診斷」內的「環境診斷」與 setup／start 使用同一組檢查。必要引擎、FFmpeg 或相依性失敗時，啟動腳本會停止並提示修復；JavaScript runtime、Chrome 或 Windows 加密的警告會說明受影響功能，不阻止其他可用下載。服務啟動時背景檢查一次，輪詢只讀快取；按「重新檢查」才再次執行本機診斷，不讀取實際 Cookie 或下載歷史，也不安裝套件或向平台發送請求。

介面 API 請求期限為 **15 秒**，包含讀取回應內容。逾時、不合法 JSON 或必要欄位不符時保留上次成功資料並顯示錯誤，按鈕恢復後可重試，狀態輪詢也會繼續。寫入請求逾時不代表操作一定失敗；介面先更新狀態，不自動重送操作，避免重複加入工作。

### 設定分頁

- **一般設定**：下載位置、每小時工作上限、重設 Rate 及無進度期限。
- **X 登入**：Chrome 登入連接、停用連接及進階 Cookie 檔案設定。頂部 X 登入入口會直接開啟此分頁。
- **診斷**：環境檢查、本機紀錄與排程健康、重新嘗試保存及匯出診斷。

頂部標題／分頁與底部按鈕固定顯示，內容區獨立捲動。切換分頁或語言會保留未儲存的輸入；按「儲存設定」會一起保存所有分頁的設定。取消或關閉會放棄未儲存的修改。分頁可用左右方向鍵或 Home／End 切換，Esc 可關閉設定。

### 自訂本機連接埠

預設為 `8765`。先停止服務，在 PowerShell 設定另一個連接埠再啟動：

```powershell
$env:SSDL_PORT = "8877"
.\start.bat
```

瀏覽器改開 `http://127.0.0.1:8877`。X 登入連接器也要在擴充功能視窗展開「本機連接設定」，輸入 **8877** 並按連接。擴充功能記住此數字，只傳送至 `127.0.0.1`；連接頁無法自動變更目的地。這不會替後端更改連接埠。`SSDL_PORT` 接受 1～65535 的整數；若已被其他程式占用，需選擇空閒連接埠。

排錯步驟見 [docs/TROUBLESHOOTING.md](TROUBLESHOOTING.md)。

只要關閉啟動程式的終端機即可停止服務。下載清單與設定會保存到本機 `data/state.json`；重新啟動後會保留項目，先前中斷的工作會重新排入佇列。下載的檔案也會保留。

## 使用方式

- 右上角 **地球圖示＋EN** 切換為英文；英文模式按 **繁中** 切回繁體中文。首次使用預設繁中，選擇保存在瀏覽器的 `localStorage`，重新整理或再次開啟後會沿用；同一瀏覽器、同一本機網址的其他已開頁面也會同步。不同瀏覽器可各自選擇語言，瀏覽器禁止儲存時仍可在當前頁面切換。
- 切換語言立即更新介面、設定、佇列狀態、SIZE / TIME、ACTION 圖示提示、工具提供的錯誤及提醒，以及 Chrome 連接安裝頁。不會重新載入頁面或中斷下載，已輸入的網址、設定草稿與篩選條件會保留。來源貼文標題、檔名、路徑與引擎原始診斷訊息保留原文。
- **重新整理網頁不會中斷下載**：下載與帳號掃描由本機 Python 後端處理，關閉或重新載入瀏覽器頁面不會停止工作；重新打開時讀取後端目前的狀態。完整頁面重新載入可能清除尚未送出的輸入與設定草稿，正在執行的下載與已保存紀錄仍保留。停止本機後端或關閉其啟動終端機才會中斷工作。
- 頂部 **更新狀態** 圓形箭頭只重新讀取 `/api/state`，不重新載入整個網頁，也不重新排入工作或向 X 抓取媒體。閒置時預設每 **30 秒**自動更新；有等待中或執行中工作時每 **2 秒**更新，方便查看掃描與下載進度；離線時每 30 秒重新連線，也可手動按按鈕立即重試。這些更新不消耗 Rate 額度、不影響平台冷卻，保留網址、設定草稿、語言與篩選條件。處理中停用按鈕，避免重複送出更新請求。
- 下載清單的篩選列採用深色底與紫色選中按鈕：左側為「全部項目／等待中／下載中／已完成／失敗」及數量，右側為平台下拉選單與搜尋。狀態和篩選文字使用 13px、數量使用 12px，窄視窗將平台與搜尋移到下一列；狀態按鈕可橫向捲動，維持文字大小。
- 下載清單使用 **分頁＋清單內捲動**：預設每頁 **20** 個工作，底部可切換 **10／20／50**，選擇保存在目前瀏覽器。清單最高為視窗高度的 60%（最多 640px），表頭固定在上方；超出高度時在清單內捲動，窄視窗可橫向查看其他欄位。底部顯示目前範圍與符合條件的總數，可按頁碼或上一頁／下一頁切換。
- 分頁以篩選及搜尋後的工作數量計算，單個 X 帳號工作內的媒體數量仍顯示在該列。切換狀態、平台、搜尋文字或每頁筆數時回到第一頁並將清單捲到頂部；手動／自動更新狀態及切換語言時保留頁碼與捲動位置。刪除或清除項目導致目前頁不存在時，會回到最後一個有效頁面。完整重新載入網頁從第一頁開始，沿用已儲存的每頁筆數。
- 清單欄寬固定分配給平台、完整日期、狀態、SIZE / TIME、檔案與操作欄，剩餘寬度供媒體來源使用。欄位左右留白一致，列內保留 12px 上下間距；標題與檔名過長時省略，滑鼠停留查看完整內容。操作欄預留 188px，28px 圖示按鈕之間保留 6px 間隔，四個操作及帳號下載時第五個停止按鈕都固定同一排。窄視窗使用清單內橫向捲動；欄位不因長標題或檔名而擠壓操作按鈕。
- 主畫面直接從安全佇列狀態列與網址輸入區開始，移除迎賓大標題及標語。狀態標題只顯示目前選擇的語言；閒置時顯示「佇列閒置／等待新任務」，正常就緒的引擎不重複顯示標記。初次檢查或引擎需更新時才顯示小型標記，滑鼠停留可查看詳細狀態或處理方式；服務無法連線時由狀態列顯示原因，窄視窗自動換行，中英文同步切換。
- 清單的「加入時間」顯示完整年、月、日與 24 小時制時間，例如 `2026/10/10 03:19`；切換英文時使用英文日期排列，既有項目也會顯示年份。
- 「媒體／來源」左側顯示 52px 縮圖。工作成功或失敗結束後，會從已保存的第一個可預覽圖片／影片產生預覽；既有項目的檔案仍在時，也會自動補上。影片優先擷取約第 1 秒，短影片或無法擷取時改用起始畫面；圖片與動畫圖片使用一幀。多檔項目右下角顯示檔案數量，影片另有播放標記，點擊縮圖使用現有播放／查看流程，多檔仍先選擇檔案。
- 縮圖以既有 FFmpeg 在獨立背景工作中產生，快取於 `data/thumbnails`，只讀取已下載的檔案，不再向社群平台請求、不計入每小時下載工作限額，也不修改原始媒體。快取會依來源檔案的路徑、容量與修改時間更新，重啟後可重用；預覽生成失敗、格式無法解碼、檔案已移動／刪除或尚未保存時，保留原本圖示。縮圖僅供預覽，不代表原始檔的畫質。[FFmpeg 文件](https://ffmpeg.org/ffmpeg.html)、[縮放濾鏡文件](https://ffmpeg.org/ffmpeg-filters.html#scale)。
- 「檔案」欄單檔項目顯示 `…\檔名.jpg`，省略前面的資料夾路徑；原本已是檔名時直接顯示檔名。滑鼠停留會顯示完整路徑，多檔項目保留媒體檔案數量並在提示中列出所有完整路徑。
- 最上方的 **Rate 已用／上限** 顯示最近 60 分鐘已啟動的工作數；每次實際啟動計一次，失敗及重新下載也會計入，同一貼文內多張圖片仍是一個工作。新版開始保存啟動紀錄後才累計此數字。
- 按右上角齒輪，在「安全佇列 → 每小時工作上限」輸入 1～1000 的整數並儲存，預設值為 40。調高上限可立即釋出額度；調低至已用數量以下時，後續工作會等待足夠的舊紀錄超過 60 分鐘。正在執行的工作會繼續完成。
- Rate 使用滾動 60 分鐘計數；清除工作清單、暫停或修改上限均保留已用計數，重新啟動也會載入尚在時間範圍內的紀錄。達上限時，頂部狀態列顯示下一個名額的等待倒數。
- 要手動歸零，點擊最上方 **Rate 已用／上限** 區塊，或按右上角齒輪 → **安全佇列 → 重設 Rate（Reset Rate）**。兩個入口都先開啟確認彈窗，顯示目前已用／上限及重設範圍；只有按 **確認重設（Confirm reset）** 才送出重設。按取消、右上角 × 或 Esc 會關閉彈窗，不改變計數；關閉後焦點回到原本入口，從設定開啟時保留設定草稿。確認窗使用原有深色／紫色風格，提供中英文文字及鍵盤操作。
- Rate 區塊滑鼠移上提示「點擊確認重設 Rate」，也可用 Tab 選取後按 Enter／空白鍵開啟確認窗。處理中顯示「重設中…」，暫時停用兩個入口與彈窗按鈕，避免重複提交；成功後關閉彈窗並顯示提示，失敗時保留彈窗與錯誤原因供再次確認。服務未連線時停用重設與確認提交。
- 設定內會顯示目前已用／上限，重設後頂部計數同步更新，直接生效，不需要再按「儲存設定」。此操作只清除本機最近 60 分鐘的啟動紀錄，每小時上限維持目前已儲存的數字，也不會儲存其他尚未送出的設定草稿。
- 重設結果會保存，重新啟動後不會恢復已清除的計數；當下正在執行的工作不受影響，其重設前的啟動紀錄一併清除，後續新啟動的工作重新計數。若有等待額度的項目，重設後仍依暫停狀態、工作延時與平台冷卻決定何時開始，因此有工作立即啟動時，Rate 可能很快從 0 變成 1。下載清單、檔案及登入連接均保留。
- 最上方的 **MB／GB（檔案數）** 統計目前下載資料夾中的常見媒體；下載完成及 X 貼文邊界增量更新，狀態讀取距離上次完整掃描超過 10 分鐘時背景校正，也可在設定 → 診斷按「重新掃描容量」。`.part`、符號連結及 Windows junction 不列入。外部搬移／刪除／新增在重掃後反映；清除清單保留檔案與容量，點擊容量可開啟資料夾。
- 最上方 **Pause** 暫停啟動後續工作，按 **Resume** 繼續；它與下載清單中的「暫停佇列／繼續佇列」使用同一狀態。正在下載的工作會繼續完成。
- 清單的 **SIZE / TIME** 上方為容量，下方為下載耗時。完成後的容量是此項目所有保存檔案的總和；下載中的容量是目前媒體的總量或預估值，來源未提供總量時顯示已接收容量。引擎提供 ETA 時會另顯示「剩餘」。
- **TIME 是下載處理耗時**，從實際啟動到成功或失敗結束，包含解析、HTTP 等待、引擎重試及影音合併，排隊與啟動前安全延時不計入。重新下載會重新計時；過去未記錄開始時間的項目顯示「耗時 —」，可讀取的既有檔案則補算容量。
- **ACTION 僅顯示圖示**：播放圖示使用 Windows 預設程式開啟影片／音訊，圖片使用查看圖示；資料夾圖示開啟所選檔案的實際所在資料夾。多檔項目會先列出檔案供選擇。檔案被移動或刪除時會顯示原因；只會開啟該下載項目已記錄的媒體檔案。
- **重新下載** 改為圓形箭頭圖示，滑鼠移上去可查看「重新取得媒體並覆寫同名檔案」的說明。垃圾桶圖示只移除清單紀錄，保留檔案；等待中／下載中的項目無法重複排入重新下載。
- 在「新增下載」（Add Downloads）貼上一個或多個影片、圖片或貼文網址。區塊說明為「貼上影片、圖片或貼文網址」，輸入框內提示每行一個網址；也可用空格或逗號分隔。
- 一次最多加入 30 個網址，佇列最多保留 200 個項目。
- 按「加入下載佇列」（Add to Download Queue）即可排入背景下載。可暫停後續工作、清除已完成或全部項目，並更改下載資料夾。

- 「清除全部」立即移除等待中與歷史項目；若有工作正在下載，會顯示「此工作完成後會自動移出清單」，並在該工作結束後移除。清理清單不會刪除檔案，也不會重置平台限流冷卻。
- 失敗與已完成項目右側都有「重新下載」，會重新取得來源並覆寫同名檔案；「重試失敗」可將全部失敗項目重新排入佇列，保留已成功的檔案。佇列暫停時，請按「繼續佇列」開始處理。
- 失敗項目會顯示中文原因，按「查看詳細原因」可讀取引擎診斷訊息。
- 支援 Twitter / X 的貼文網址，也可貼上圖片 CDN 直連。同一貼文的多張圖片及影片會分別保存，清單會顯示檔案數。
- 依來源分工使用 yt-dlp、gallery-dl 及直接 HTTP 下載，詳細說明見下方「下載引擎」。套件內的 FFmpeg 用來合併影音串流，保留原有編碼，沒有設定轉碼或重新壓縮。
- Twitter / X 圖片只要求 `orig` 尺寸；原尺寸不可取得時回報失敗，不會退回小圖或下載影片預覽圖。X 影片選擇平台回傳的最高位元率版本。
- X 未登入時使用公開嵌入端點，保存該端點提供的同篇貼文圖片與影片，並顯示公開端點可能提供較少媒體的提醒；不將引述貼文混入下載。X 訪客驗證端點失效時，公開貼文仍可使用這個方式。
- X 公開資料未提供媒體或需要登入時，按右上角「連接 Chrome 登入」。工具先嘗試讀取 Chrome 最近使用的個人檔案中 X 的登入狀態；若 Chrome 加密或鎖定 Cookie，會在一般 Chrome 開啟本機連接頁。透過 Chrome 正式 cookies API 使用已登入的 X，不再開啟受控的專用登入瀏覽器。
- **首次連接器設定只需一次**：在一般 Chrome 開啟 `chrome://extensions`，啟用右上角「開發人員模式」，按「載入未封裝項目」，選擇專案內的 `chrome-extension` 資料夾。回到本機連接頁並重新整理，即可自動連接；也可按「連接已登入的 X」。工具設定的「Chrome 連接器安裝步驟」提供可複製的完整資料夾路徑。這是 Chrome 官方支援的本機安裝方式，Chrome 要求使用者自行載入一次，工具不會強制安裝。
- 之後按工具的「連接 Chrome 登入」，或 Chrome 擴充功能的「連接已登入的 X」即可。成功後自動重試失敗的 X 項目，不需要匯出 Cookie。若該 Chrome 個人檔案尚未登入 X，請先在一般 Chrome 手動登入或完成 Google／Apple 登入，工具不會提交帳密或重試登入。
- 設定中的「在一般 Chrome 開啟 X」會打開日常使用的 Chrome。「取消登入／停用連接」停止工具使用登入狀態並移除加密保存的登入檔案，不會登出你平常使用的 Chrome。下載中的工作可能已取得登入狀態，停用設定影響後續工作。
- 僅讀取 X 網域的 Cookie，保留 auth_token、ct0、twid。登入資料在 Windows 下以目前使用者的 DPAPI 加密保存於 `data/x-auth.bin`，不放進 API 回應、下載清單或紀錄。連接器只將登入資料傳送到本機 `127.0.0.1`，預設連接埠為 `8765`，可在擴充功能視窗設定成後端使用的數字；傳送需有受限來源與一次性連接憑證。不讀取 Google／Apple Cookie，也不傳送至第三方服務。
- **Windows 加密保存失敗**：關閉目前服務，從一般 Windows 桌面執行 `start.bat`，再重新整理連接頁並連接。受限制的自動化程序或沙箱可能無法使用使用者的 Windows 加密金鑰；反覆登入 X 無法解決此本機錯誤。失敗的配對會清除頁面上的一次性票證，下次點擊重新取得；連接／等待期間每兩秒更新狀態，也可以取消等待。
- 若 X 顯示暫時限制登入，請停止反覆登入並依 X 官網說明等待；多次登入失敗造成的鎖定通常約一小時後解除。此工具不能解除帳號限制。官方說明：https://help.x.com/en/managing-your-account/locked-out-after-too-many-login-attempts
- 舊有 Netscape 格式 `cookies.txt` 仍可在設定的「進階：使用 Cookie 檔案」中使用；如需切換到檔案，請先停用 Chrome 連接，再填入完整路徑並儲存。僅讀取其中 X 的有效登入 Cookie；不要分享此檔案。兩種登入方式皆未設定時使用公開貼文資料。
- 其他影片優先選擇最高可用視訊與音訊串流；不強制改成 MP4，保留來源編碼及適合的容器格式。圖片則直接保存來源內容，不進行重新編碼。
- 「原尺寸 / 最高畫質」指平台可提供的檔案。平台若在上傳時已壓縮或轉碼，無法還原上傳者電腦內的原始檔案；平台回報品質限制時，清單會顯示提醒。
- 實際可下載的網站與格式仍受平台、內容權限及解析器支援狀況影響，不能保證任何網址都能下載。已刪除、無存取權限、付費或 DRM 內容可能無法取得；提供 Cookie 也不能保證可下載。
- YouTube 的完整解析支援還需要系統中的 **Node.js 22+ 或 Deno 2.3+**；環境診斷會檢查執行檔與版本。安裝及加入 PATH 後重新啟動服務，工具不會自動安裝全域 runtime。詳見 [yt-dlp 官方 EJS 說明](https://github.com/yt-dlp/yt-dlp/wiki/EJS)。

## 平台資料夾

在設定指定的下載資料夾下，所有新保存的媒體都按平台分類。資料夾在第一次使用該平台時建立，名稱使用固定的小寫平台名稱，繁中／英文切換不會改變實際路徑。

| 來源 | 保存位置範例 |
| --- | --- |
| YouTube／Shorts／youtu.be | `downloads/youtube/影片標題 [影片ID].mkv`（副檔名依來源與合併結果） |
| X／Twitter 貼文與帳號 | `downloads/twitter/帳號/貼文ID_序號.jpg` |
| Instagram／Pinterest 等社群貼文 | `downloads/instagram/帳號/...`、`downloads/pinterest/帳號或相簿/...`；保留解析器原有子資料夾與檔名。 |
| TikTok／抖音／Facebook／Threads | `downloads/tiktok/...`、`downloads/douyin/...`、`downloads/facebook/...`、`downloads/threads/...` |
| Bilibili／Vimeo／Twitch／Reddit | `downloads/bilibili/...`、`downloads/vimeo/...`、`downloads/twitch/...`、`downloads/reddit/...` |
| 圖片直連 | 可辨識的平台 CDN 使用對應資料夾，例如 X 圖片存到 `downloads/twitter/檔名 [網址指紋].jpg`；其他來源使用安全化的網域名稱。 |
| 其他解析器支援的平台 | 使用解析器的平台分類名稱，保留其帳號、相簿等子資料夾；一般影片無法辨識平台時使用來源網域。 |

清單保存相對於下載根目錄的實際路徑；播放／查看、開啟資料夾、縮圖與容量統計沿用這個位置。換成自訂下載資料夾時，也會在該位置建立相同的分類結構。既有成功紀錄中的檔案仍依記錄的原位置檢查；移動舊檔案時須一併更新紀錄，才能保留播放、縮圖及去重的正確位置。

## 已下載檔案檢查

- **原位置檢查**：下次加入網址或同步時，檢查原下載資料夾及原檔名。檔案被搬移、刪除、改名，或更換下載資料夾時會重新下載；不搜尋其他位置，也不背景監看檔案。
- **同一來源沿用原項目**：再次加入相同來源、相同下載資料夾時，沿用已有的完成或失敗項目並重新檢查，不新增重複列；一般媒體來源已等待或下載中時不重複排隊。X 單篇依貼文編號識別，`x.com`／`twitter.com` 及追蹤參數的差異不會新增另一列。
- **略過狀態**：圖片直連、gallery-dl 及 yt-dlp 略過已存在檔案時，本頁觀察到該次工作完成後顯示「已略過，檔案已存在」。重新整理或重新開啟頁面後，歷史項目顯示「已完成」；滑鼠移上可查看上次略過的說明。略過紀錄仍保存在本機，頁面自動更新與語言切換不會提前清除本次提示。解析平台媒體清單仍可能花時間及請求。
- **圖片直連**：成功後保存本機紀錄，原位置的檔案大小與修改時間相符時略過，依上述規則顯示本次提示。按「重新下載」仍會重新取得來源並覆寫同名檔案。
- **X 帳號**：略過已完整保存的貼文；有逐檔紀錄時只補下載缺少或變更的媒體。也能納入仍保留於清單、檔名與容量符合的單篇成功下載，避免第一次同步重抓。
- **一般影片／貼文**：使用媒體 manifest 記錄來源、原位置、大小、修改時間及成功完成狀態，核對已保存檔案；未確認完成的同名檔案不足以直接略過。目前沒有跨網址或跨平台的內容雜湊去重。

各模式的實作、紀錄位置、舊檔案匯入條件及後續優化整理於 [docs/DOWNLOAD_DEDUP.md](DOWNLOAD_DEDUP.md)。清除清單保留已建立的保存紀錄及下載檔案。

舊清單中可確認來源、下載資料夾及檔案集合相同，且檔案仍在原位置、容量符合的重複完成列，啟動時保留最新一列並合併執行次數；X 帳號同步歷史保留。合併前備份原清單到 `data/state.before-row-dedup-*.json`，不刪除下載檔案，也不修改每小時額度紀錄。

## X 帳號媒體下載

1. 在「新增下載」選擇 **X 帳號媒體（X Account Media）**。
2. 按 **連接 Chrome 登入**，使用你已登入的 X；設定中的 Cookie 檔案也可沿用。帳號歷史需要登入，單篇貼文的公開嵌入端點無法列出帳號所有媒體。
3. 貼上 `https://x.com/username`、`https://x.com/username/media` 或 `@username`。可一次貼上多個帳號，每行一個，也支援空格或逗號分隔，一次最多 30 個。
4. 按 **加入下載佇列**。帳號作為一個清單項目依序處理：先掃描清單並核對原位置的已下載檔案，掃描完整成功後顯示 **總檔案數／需要下載／已存在**，再開始下載。一般「媒體網址」模式貼入 X 帳號首頁或媒體頁時，也會自動辨識為帳號下載。

- **範圍**：取得該帳號發布的圖片與影片，包含回覆中的媒體，排除轉發、引述來源、頭像、橫幅、影片預覽圖及純文字貼文；不抓其他作者的媒體。使用 gallery-dl 的 `timeline` 解析器，先走媒體時間軸，再以歷史搜尋取得平台可提供的較早內容。沒有設定固定貼文數上限，也不將 200 個清單項目的上限當成媒體數上限。
- **畫質與路徑**：圖片要求 `orig`，影片選擇最高位元率，保持來源格式；存到目前下載資料夾的 `twitter/帳號/貼文編號_序號.副檔名`，與單篇 X 下載的命名方式相同。
- **再次執行與中斷續抓**：完成或中斷後，按圓形箭頭可同步新增或未完成媒體。每篇完整保存後，將貼文編號及逐檔紀錄保存到本機 `data/x-profiles.sqlite3`，依帳號及實際下載資料夾分開；原檔名、媒體數量及保存檔案相符時才略過，新紀錄並檢查大小與修改時間。缺檔、搬移、改名或變更的媒體會補下載，仍符合逐檔紀錄的檔案保留。舊單篇只有合計大小、部分檔案已缺少時，重新取得該篇媒體。清除清單保留此紀錄及檔案，改換下載資料夾會使用該位置的下載紀錄。
- **Safe Queue／Rate**：每篇需要下載的媒體貼文計入一次共用每小時工作額度，多張媒體仍算一篇；已完整保存而略過的貼文不消耗額度。貼文間同樣隨機延時 3～8 秒、HTTP 請求間隔至少 1 秒，遵守限流冷卻。達到每小時上限會等待額度釋出，因此大量帳號歷史可能需要數小時或更久。
- **暫停／停止**：Pause 在目前貼文完成後暫停後續處理，Resume 繼續。方形停止圖示會結束目前下載程序並保留已保存／部分檔案；項目顯示「已停止」，歸在失敗篩選中以便同步重試，重新連接登入不會自動恢復使用者已停止的項目。「清除全部」也會停止目前工作並移除紀錄，下載檔案及保存紀錄保留。
- **先掃描總數**：完整讀取媒體時間軸及引擎提供的歷史搜尋結果，逐篇去除重複貼文並計算圖片與影片檔案數。掃描時顯示「已找到」的累計數量；只有掃描成功結束才標示為「總檔案數」。一篇貼文有 4 張圖片即計為 4 個檔案。掃描後首次需要下載的貼文仍等待 3～8 秒安全延時，讓介面先顯示數量。
- **已存在與需要下載**：依本機保存紀錄與原路徑、大小、修改時間核對，將已驗證的檔案列入已存在數量，其餘列為本次需要下載。實際處理每篇貼文前再次核對；掃描期間檔案被搬移、刪除、改名或變更時，更新需要下載數量並補抓。已存在檔案也列入檔案完成進度；Rate 仍按需要下載的貼文計數，一篇多個檔案只算一個工作。
- **掃描暫存與失敗**：媒體清單使用 `data` 目錄內的暫存檔逐篇保存及讀取，避免將整個帳號的貼文資料保留在記憶體；結束、停止或失敗時關閉並移除暫存檔。掃描同樣使用 X 登入與 HTTP 節流／冷卻，支援暫停及停止。掃描未完整成功時不開始下載新的媒體，只保留「已找到」數量與錯誤原因；重新同步或重啟後重新掃描，既有檔案及保存紀錄保留。
- **進度與耗時**：總數是本次成功掃描到的可存取媒體數量，不使用 X 帳號頁的概略媒體數推算。下載時顯示「已完成／總檔案數」、剩餘數量及檔案數進度條，完成與失敗後仍保留本次掃描結果；舊版工作沒有預掃描紀錄時保留原有累計顯示，下次同步才取得總數。SIZE 為累計已保存檔案容量，下載中另加目前已接收容量；TIME 從帳號工作開始到結束，包含預掃描、限額等待、暫停及合併，排入佇列前的等待不計入。大量檔案的選擇視窗每次顯示 100 個，按「顯示更多檔案」繼續；帳號的檔案欄提示列出前 20 個完整路徑及剩餘數量。
- **可取得範圍**：完成代表平台目前提供的內容已處理，並不保證整個歷史都可取得。已刪除、私人、無權限、搜尋未收錄或受 X API 限制的內容可能缺漏；平台回報的問題與範圍提醒可在下載提醒或詳細原因查看。沒有可見媒體時會顯示空結果提醒。

解析策略與選項參考：[gallery-dl 官方設定文件](https://gdl-org.github.io/docs/configuration.html#extractor-twitter-timeline-strategy)。

## 安全佇列的延時與限流

- **每小時額度**：預設 40 個工作，與 HTTP 請求間隔分別計算。可在設定中修改上限，儲存後立即套用，並保存至本機設定檔；提高額度仍會遵守工作間延時、HTTP 節流及平台限流冷卻。
- **重設 Rate**：可手動清除本機已用額度，重新累計後續工作的啟動次數。重設會喚醒等待額度的佇列，但不取消暫停、安全延時、HTTP 請求間隔或平台限流冷卻。
- **工作間延時**：不論新工作、個別重新下載、批次重試或 X 登入後自動重試，均由同一個 worker 依序處理。上一項成功或失敗後，都會隨機設定 3～8 秒間隔。閒置時間已超過這個間隔時，新加入的工作可直接開始。
- **請求間隔**：共用節流器將 Python 下載引擎的新 HTTP 呼叫限制為至少間隔 1 秒；yt-dlp 與 gallery-dl 的解析請求也啟用引擎內的間隔設定。gallery-dl 關閉非同步解析，yt-dlp 使用單一片段下載並優先使用原生 HLS 下載。這是請求頻率限制，沒有另外限制檔案傳輸的每秒位元組數。
- **限流冷卻（平台冷卻）**：平台回報「請求太頻繁」（例如 HTTP 429），或引擎辨識到平台限流錯誤時，工具會暫停抓取、等待再繼續，以減少連續觸發限制。第一次至少等待 60 秒；連續觸發時延長為 2、4、8、15 分鐘（60、120、240、480、900 秒的退避）。若平台提供更長的 `Retry-After`，優先依其要求等待（最多一天）；成功完成工作後重置連續限流計數。預設各平台獨立冷卻；排程可先處理其他符合條件的平台。設定成共用模式時，所有平台的後續下載都會等待。切換模式保留既有冷卻，狀態列顯示目前工作的倒數。重設 Rate 只清除本機工作計數，平台冷卻仍會繼續倒數。
- **冷卻結束**：倒數結束後，尚在佇列中的等待項目會自動繼續依序處理，仍遵守暫停狀態、每小時額度與安全延時。
- **失敗重試**：已標記為失敗的項目不會因冷卻結束就自動重試；需按「重新下載」或「重試失敗」。成功連接 X 登入後的自動重試也遵守相同規則。
- **暫停與重啟**：暫停停止啟動後續工作，正在執行的單篇工作會繼續完成；X 帳號模式在目前貼文完成後暫停。延時及冷卻資訊與下載清單一起保存在本機，重新啟動後會繼續遵守尚未結束的冷卻；中斷的帳號工作重新掃描歷史，略過已完整保存的貼文。
- **作用範圍與限制**：節流涵蓋工具管理的 Python HTTP 呼叫；引擎內部的連線重新導向或外部程式自行發出的請求，不一定逐次經過同一節流器。延時與限流用於降低請求頻率，不能保證不被平台限制、封鎖或要求驗證，也不能解除帳號限制。

## 下載引擎

目前有使用 **yt-dlp**。依網址及解析器支援情況，分工如下：

| 來源／用途 | 使用方式 |
| --- | --- |
| 一般影片網址 | 使用 yt-dlp 解析及下載，選擇最高可用影片與音訊串流。 |
| 引擎不支援的普通網頁 | 自動啟動本機通用解析層；找到 MP4、WebM、HLS、DASH 等來源後交回 yt-dlp，已支援的嵌入播放器也交給平台解析器。 |
| 社群貼文、多張圖片及已登入的 X 媒體 | 優先使用 gallery-dl 的平台解析器；需要影片解析時可交由其 yt-dlp 下載器處理。 |
| 未登入的 X 單篇貼文 | 讀取 X 公開嵌入資料，使用 gallery-dl 保存原尺寸圖片及公開端點提供的最高位元率影片；使用 yt-dlp 的工具函式計算該端點需要的參數。 |
| 已登入的 X 帳號媒體 | 使用 gallery-dl 的媒體時間軸與歷史搜尋逐篇列出並下載，沿用單篇最高畫質策略、本機保存紀錄及共用安全佇列。 |
| 圖片直連 | 直接保存來源位元組，X 圖片要求 `orig` 尺寸。 |
| 影音串流合併 | 使用套件附帶的 FFmpeg，保留來源影音編碼。 |

本次功能更新前，正在運行的環境回報 yt-dlp `2026.08.19`、gallery-dl `1.32.16`，兩個引擎及 FFmpeg 均可用。這是當時的環境版本，之後更新套件可能會改變；目前版本可從本機 `http://127.0.0.1:8765/api/state` 的 `engines` 欄位查看。

上游文件：[yt-dlp](https://github.com/yt-dlp/yt-dlp)、[gallery-dl 設定說明](https://gdl-org.github.io/docs/configuration.html)。

## 選擇影片畫質

在「新增下載 → 媒體網址」使用「影片畫質」下拉選單，預設 **最高畫質**，也可選 **2160p、1440p、1080p、720p、480p、360p、240p、144p**。這些是下載偏好，不是預先讀取每個播放器後列出的實際畫質；不增加確認彈窗。

- 指定數字代表影片高度上限：選 720p，會選最高且不超過 720p 的版本；若來源只有 1080p／480p，就下載 480p。不放大、不重新編碼。沒有符合上限的版本或來源未提供解析度時，顯示原因並保留失敗紀錄，不自動下載超過上限的版本。
- 圖片仍保存原尺寸及來源位元組。單篇 X 貼文可選其公開或登入資料提供的 MP4 版本；「X 帳號媒體」整批同步目前維持最高畫質，切換回媒體網址後保留原本的下拉選擇。
- 畫質選擇隨工作保存，重新下載沿用該工作的設定。改變上方選單不會修改既有工作；要下載另一種畫質，改選後再貼入同一網址加入。
- 不同畫質偏好分開工作與完成紀錄。指定 720p 的檔案存到平台底下的 `quality-720p` 子資料夾，保留原本最高畫質的檔案；同樣的偏好再次加入，仍核對原位置完整檔案。多媒體貼文／相簿中的原尺寸圖片也保存到該版本資料夾；圖片直連仍使用共用的圖片紀錄。
- 新開或重載頁面時預設最高畫質；一般狀態自動更新不重設下拉選擇。

詳細選取、保存及限制見 [VIDEO_QUALITY.md](VIDEO_QUALITY.md)。

## 多播放器、冷卻分組與操作整理

- 通用網頁出現多個播放器時，工作顯示「待選擇」，按該列選擇圖示選定後才排入下載；等待選擇不占用 worker，其他工作可以繼續。同一播放器的多個畫質依畫質選單處理，不逐一詢問。
- 設定 → 一般提供「各平台獨立冷卻」（預設）及「全部平台共用冷卻」。各平台仍共同遵守 Rate、單 worker、3～8 秒工作延時與請求間隔。切換模式與重設 Rate 都保留既有冷卻。
- 前端文案改用 `static/locales.js` 的固定 key。彈窗支援 Tab／Shift+Tab 焦點循環、Esc 關閉最上層及焦點返回；窄視窗保留篩選與表格捲動。
- 紀錄升級為 schema 2，相容讀入 schema 0／1；舊版程式不應覆寫新版紀錄。

完整分組規則、目錄、限制與尚待驗收的項目見 [P2_COMPLETION.md](P2_COMPLETION.md)。

## 通用網頁媒體解析

- **如何使用**：沿用「媒體網址」輸入區貼上網頁網址、加入下載佇列，不需選擇網站框架或另外啟動模式。平台解析器及 yt-dlp 先處理；只有 yt-dlp 回報不支援網址時，才自動啟動後備解析。登入、權限、404、網路或限流錯誤保留原本原因。
- **解析範圍**：讀取 HTML5 `video`／`audio`／`source` 標籤（含 `data-src`）、Open Graph 影片資訊、Twitter Player 資訊、JSON-LD `VideoObject`、內嵌 JSON 播放器設定，以及腳本中的明確媒體網址。處理相對路徑、HTML 實體、JSON／Unicode 跳脫、百分比或 Base64 編碼的普通 URL，以及播放器網址參數內的媒體連結；規則沒有綁定特定網站、CMS 或播放器變數名稱。
- **嵌入播放器**：原頁沒有可用來源時，沿 `iframe` 或媒體資訊中的播放器網址讀取嵌入頁面。引擎已支援的嵌入播放器交回其平台解析器，其餘繼續以相同通用規則解析。只追蹤播放器，沒有遍歷全站連結。
- **選擇與畫質**：優先嘗試明確播放器來源及串流清單，依提供的畫質標記排序候選來源；HLS／DASH 內的畫質、影音選擇及片段下載由 yt-dlp 處理，沿用最高可用影音與 FFmpeg 保留編碼合併。不同播放器先分組並讓使用者選擇，同一播放器的畫質版本依設定取得；成功保存選定播放器的一個可用來源即結束本次後備解析。它不是整頁相簿或多個獨立影片的批次掃描。
- **HTML5 畫質辨識**：一般影片按來源回報的解析度優先選擇。通用 HTML5 頁面另外讀取 `size`、`data-height`、畫質標籤，以及檔名中明確的 `1080p`／`1920x1080` 標記，補足缺少的尺寸；不覆蓋引擎已回報的尺寸、不把網址 query 或單純編號當作畫質。避免來源從高到低排列時誤選最後一個低畫質版本。清單顯示選中的尺寸或高度；缺少資訊時顯示「解析度未回報」。這是來源標示，不能保證視覺品質或還原上傳原檔。已完成檔案不會自動升級，請按該列「重新下載」圖示取得目前最高可用版本，完成後替換同名檔案。詳見 [VIDEO_QUALITY.md](VIDEO_QUALITY.md)。
- **請求資訊**：媒體下載保留 Referer，並可沿用本次公開網頁收到的短期 Cookie；不讀取一般 Chrome 登入資料，也不把臨時 Cookie 寫入清單。靜態解析不執行 JavaScript；新增選配動態影音捕捉，執行 `python tools/manage.py browser-setup`、重新啟動，再於「設定 → 一般設定」啟用。它會用臨時 Chrome 捕捉 MP4／HLS／DASH 及執行時 HTML5 來源，沿用畫質與播放器選擇。`blob:` 仍須找到底層 HTTP 串流；不自動登入或點擊頁面按鈕，不處理 DRM、WebSocket、僅 POST 或互動驗證。臨時瀏覽器資料的清理與限制見 [DYNAMIC_CAPTURE.md](DYNAMIC_CAPTURE.md)，驗收見 [TESTING.md](TESTING.md)。
- **資料夾與檔名**：媒體即使位於另一個 CDN 或嵌入平台，也存到原始網頁對應的平台資料夾。直連候選以網頁標題及 `web-來源識別` 命名；識別結合原頁網址及完整媒體 URL（保留 query，只排除 fragment），避免同一路徑、不同媒體 ID 或畫質被合併。無法確認簽章參數的語意時也保留，因此更新簽章可能產生新的檔案識別。嵌入平台保留其來源 ID。相同識別在原位置已有完成檔案時略過；搬移、刪除、改名或換下載位置時重新取得。後備來源切換時不接續其他候選的 `.part` 檔案。
- **安全佇列**：解析與下載仍是同一個工作，不因候選網址增加而另外累計 Rate。後備網頁解析的 HTTP 請求及重新導向套用共用節流，媒體下載沿用引擎的請求節流和限流冷卻。每次最多檢查 6 個頁面、追蹤 2 層嵌入、保存 12 個候選、嘗試 6 個來源；每頁最大 2 MiB，掃描時間預算 60 秒，影音下載時間另計。
- **失敗與後續工作**：若沒有找到來源，顯示通用解析結果；找到但無法下載時，詳細原因保留掃描頁數、候選數及引擎錯誤，候選診斷省略網址中的簽名參數。失敗項目會釋放 worker，後續工作依原有延時、Rate、暫停與平台冷卻規則繼續；沒有自動無限重試。

yt-dlp 本身也提供通用解析器，本機後備層用於補充它未能辨識的網頁來源；不能保證任意網站皆可下載。[yt-dlp 通用解析器原始碼](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/generic.py)。

## Chrome 連接器的維護與更新

Chrome 連接器偶爾需要維護。它目前只透過 Chrome 官方 Cookie API 讀取 X 的登入資料，再傳給本機下載工具，沒有解析 X 網頁。一般使用不需要修改程式碼，但不能保證永遠不用更新。

**現有連接器升級到 1.1.0**：在 `chrome://extensions` 按重新載入一次，再重新整理本機連接頁。此版新增 `storage` 權限保存本機連接埠；擴充功能不保存 X Cookie 副本。新使用者仍依首次載入步驟安裝。

- **登入到期或登出**：先在一般 Chrome 重新登入 X，再按「連接 Chrome 登入」或擴充功能的「連接已登入的 X」。這是重新連接登入狀態，通常不需要更新程式。
- **程式可能需要更新的情況**：Chrome 的 Cookie API 或權限規則改變、X 的登入 Cookie 或驗證方式改變，或本機下載工具的 API、網址及連接埠改變。
- **目前是本機載入版，不會自動更新**：首次「載入未封裝項目」完成後，更新同一資料夾內的連接器檔案即可；更新後仍需手動重新載入。

連接器檔案更新後，依序操作：

1. 在一般 Chrome 開啟 `chrome://extensions`。
2. 找到「Smart Social Downloader · X 連接器」，按「重新載入」。
3. 重新整理本機連接頁，再按「連接已登入的 X」。

若移動了專案資料夾，請在 Chrome 擴充功能頁移除舊的連接器，重新「載入未封裝項目」並選擇新位置的 `chrome-extension` 資料夾。

官方文件：[Chrome Cookie API](https://developer.chrome.com/docs/extensions/reference/api/cookies)、[本機載入與重新載入擴充功能](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world)。

## 程式與下載引擎更新

更新程式碼後，先停止服務；需要補齊或恢復發布時的套件版本時執行 `setup.bat`，再用 `start.bat` 啟動。一般啟動不更新套件。

需要更新解析器時執行 `update.bat`，或 `.venv\Scripts\python.exe tools/manage.py update`，完成後重新啟動服務。

## 串流完整性與本機 API

HLS／DASH 片段最多重試 3 次；仍無法取得任何必要片段時，工作回報失敗，不把缺片結果當成完整影片。gallery-dl 委派給 yt-dlp 的串流也沿用相同政策；音訊缺失或影音合併失敗均保留失敗結果，可在來源恢復後重試。過去已完成的檔案不會因此自動重新驗證。

本機 API 會檢查 Host／Origin 及瀏覽器跨站請求資訊，拒絕其他網站讀取下載紀錄或操作工具；不限制你貼入的媒體網站，正常介面與 Chrome 配對可繼續使用。詳細說明見 [docs/RELEASE.md](RELEASE.md)。

## 清單效能與快取

狀態輪詢只傳目前頁面的工作摘要；每項最多 20 個路徑預覽，總檔案數不受預覽數限制。檔案選單每批最多取得 100 個檔名，查看提醒及失敗原因時才讀取完整診斷。所有完整檔案清單仍保存在後端，去重與開啟檔案檢查保留。

未變動的資料列與欄位保留，縮圖不因輪詢反覆重建；切換頁面或篩選會忽略舊請求晚到的結果。設定 → 診斷新增容量重掃及縮圖快取清理，清理只移除生成的預覽，之後可重新產生，不刪除原始媒體。

合成 200 工作／100,180 檔案的工作清單從 4,563,700 bytes 降至 23,350 bytes（約減少 99.5%）。這是摘要建立與 JSON 編碼量測，不包含完整 HTTP／磁碟耗時。API、回收限制及驗收範圍見 [PERFORMANCE.md](PERFORMANCE.md)。

## 下載可靠性、保存與診斷

- 一般媒體與 X 帳號都可停止目前工作。每項下載在獨立程序執行，停止會結束該工作及所屬合併工具，保留已保存檔案／部分檔案，後續佇列繼續。
- 設定 → 安全佇列 → **無進度逾時**，預設 **300 秒**，可設 **30～3600 秒**，供下一個工作使用。持續接收資料、進度變更或合併 CPU 活動會更新計時；Rate／冷卻／暫停的排程等待除外，不按影片總耗時判斷失敗。
- 一般下載新增 `data/media-manifest.sqlite3`：確認來源、原位置、大小、修改時間及完成狀態才略過。YouTube 同影片的不同網址使用穩定 ID；搬移、改名、移除或換下載位置時重新取得，不搜尋搬走的檔案。沒有可信成功紀錄時不只憑同名檔案略過。
- `data/state.json` 加入版本及有效備份 `state.json.bak`。損壞可從有效備份恢復；較新版本不覆寫。設定顯示保存錯誤，修正空間／權限後可按「重新保存紀錄」。
- 下載來源另受公開 HTTP／HTTPS 檢查：DNS、實際連線、重新導向、HLS 金鑰／片段及 DASH 資源都拒絕回環／內網。原生 HLS／DASH 與本機 FFmpeg 合併可用；系統 proxy、curl impersonation、RTMP／外部 FFmpeg 網路下載不在此傳輸政策支援內。這不阻止正常介面讀取本機 API，也不是作業系統沙箱。
- 設定可**匯出診斷**，包含已遮蔽錯誤及環境／worker／保存狀態，不含媒體網址、標題、檔案清單、下載路徑或實際 Cookie；不會自動傳送給別人。

本機 HTTP 服務最多同時處理 32 條連線；標頭與 body 共用 10 秒絕對讀取期限，socket 寫入期限 5 秒。過載回覆 503／Retry-After，body 不完整而逾時回覆 408。POST 需唯一的 Content-Length（1～100,000 bytes），不支援 chunked body。這些傳輸限制不會停止背景下載，也不限制 API 內部磁碟操作的耗時。暫停 API 只接受明確的 boolean；錯誤 Cookie 輸入回覆 400，保留既有登入與有效配對票證。

完整流程、限制及測試範圍見 [docs/RELIABILITY.md](RELIABILITY.md)；移動／改名規則見 [去重政策](DOWNLOAD_DEDUP.md)。

維護測試使用暫存 fixture、合成 DOM／連接器 API 及臨時無頭 Chrome，不需要私人帳號；Node.js 22+ 的前端測試不用安裝 npm 套件。先以 `python tools/manage.py browser-setup` 安裝選配套件並安裝一般 Chrome，才會執行瀏覽器測試；缺少時會明確略過，不算完整驗收。結果與剩餘環境驗收見 [TESTING.md](TESTING.md)：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --test tests/frontend.test.cjs
.\.venv\Scripts\python.exe tools/package_source.py --check
```
