# 安裝、狀態更新與 X 登入排錯

對應 [CHANGELOG](../CHANGELOG.md) 已完成的 R05、R07、R10；待驗收項目見 [Roadmap](../ROADMAP.md)。一般使用者依英文或繁中 README 安裝；本文件補充異常的處理方式。

## 1．安裝與環境診斷使用相同規則

首次執行 `setup.bat`，之後使用 `start.bat`。`update.bat` 是使用者主動更新引擎的入口，更新前先停止服務；一般啟動不安裝或更新套件。

命令列及設定 →「診斷」中的「環境診斷」共用以下檢查：

| 項目 | 判定方式 | 需要處理時 |
| --- | --- | --- |
| Python | 3.12 安裝／CI 基準；最低 3.12 | 安裝 Python 3.12；舊虛擬環境版本過低時，停止服務並重建 `.venv`，再執行 setup。 |
| yt-dlp、gallery-dl、imageio-ffmpeg | 能匯入且有版本資訊 | 執行 setup 恢復基準，或停止服務後主動 update。 |
| FFmpeg | 實際執行版本命令；先使用 PATH，再嘗試內附版本 | 修正失效的 PATH 執行檔，或執行 setup。 |
| 套件相依性 | `python -m pip check` 成功 | 執行 setup 恢復一致的套件版本。 |
| JavaScript runtime | PATH 中的 Node.js 22+ 或 Deno 2.3+ 可執行 | 安裝符合版本的 runtime、加入 PATH，再重新啟動服務。 |
| yt-dlp-ejs | 能匯入且有版本資訊 | 恢復基準套件；YouTube 完整解析也需要可用 runtime。 |
| 專案 .venv | 使用專案的 Python 環境 | 從 start.bat 啟動。 |
| Chrome | 找到一般 Chrome 執行檔 | 安裝 Chrome；連接器仍須在已登入 X 的個人檔案自行載入一次。 |
| Windows 登入加密 | 用固定診斷文字測試加密及解密 | 從一般 Windows 桌面啟動 start.bat。 |
| 本機連接埠 | SSDL_PORT 為 1～65535 的整數 | 修正設定；Chrome 連接器選定相同連接埠。 |

必要的 Python、引擎、FFmpeg、相依性或連接埠設定失敗，啟動腳本會停止並顯示修復提示。JavaScript runtime、Chrome、登入加密或 .venv 警告說明特定功能需要注意，不阻止其他可用下載。Chrome 存在不代表連接器已載入或 X 已登入。

Node.js／Deno 最低版本依 [yt-dlp 官方 EJS 說明](https://github.com/yt-dlp/yt-dlp/wiki/EJS)。診斷不自動安裝全域程式。

服務啟動時在獨立執行緒檢查一次；開啟設定或輪詢只讀取快取。按「重新檢查」可再次執行；同一時間只執行一次，不占用下載 worker。外部診斷命令各有逾時。診斷不讀取實際 Cookie 或下載歷史、不向平台發送請求、不安裝套件。加密檢查只使用固定合成文字。

安裝程式或變更 PATH 後，需要重新啟動服務讓它取得新的環境；單純重新整理網頁不會更新服務的 PATH。

## 2．網頁更新失敗時

主介面 API 使用共用客戶端，請求期限 **15 秒**，包含等待回應與讀取 JSON。Chrome 連接器的背景 API 請求期限為 **12 秒**。

- 回應不是 JSON、JSON 損壞或必要欄位不符：顯示錯誤，保留上次成功資料，不把空物件當成最新狀態。
- 無法連線或逾時：檢查服務終端機是否仍在執行，按頂部更新按鈕重試。
- 狀態更新失敗：清單保留但可能不是最新資料，狀態列會顯示原因與上次成功時間。
- 讀取成功後恢復正常輪詢：閒置每 30 秒、下載／等待／登入連接／環境檢查期間每 2 秒更新；更新失敗每 30 秒重試。
- 操作按鈕在請求結束後恢復可用，仍依工作狀態決定是否可點選。

**寫入逾時不等於操作未執行。** 例如加入工作後，後端已排入佇列，但回應來不及送到網頁。介面不會自動重送加入、清除、重設或登入操作，會先讀取狀態；確認最新結果後再決定是否重試。

網頁重新整理不停止後端下載；未送出的網址或設定草稿可能遺失。停止或重新啟動服務是另一件事，執行前應先完成或暫停下載。

## 3．X 登入與 Windows 加密

先在日常使用的 Chrome 個人檔案登入 X，再連接。首次載入連接器一次，之後通常只需按連接或同步。

連接器先向本機服務取得一次性票證；服務先檢查 Windows 加密能力，再允許連接器讀取所需的 X Cookie。保存失敗會回報到主介面，頁面清除失敗嘗試的票證，下次重新取得。

若顯示「Windows 無法保存或讀取登入狀態」：

1. 確認沒有進行中的下載，關閉目前服務。
2. 從一般 Windows 桌面執行 `start.bat`；受限制的自動化／沙箱程序可能不能使用目前使用者的 Windows 加密金鑰。
3. 重新整理本機連接頁，再按連接。

這不是 X 帳號驗證錯誤，反覆登入 X 無法修復本機加密問題。若 X 本身顯示暫時限制登入，依平台提示等待；連接器不能解除帳號限制。

**既有連接器更新到 1.1.0**：在 `chrome://extensions` 按重新載入一次，再重新整理本機連接頁。1.1.0 使用 `storage` 權限保存選定的連接埠；不在擴充功能保存 Cookie 副本。載入及移除方式見 [連接器文件](../chrome-extension/README.md)。

## 4．自訂連接埠必須一致

預設 `8765`。若需要 `8877`，先停止服務，在 PowerShell 啟動：

```powershell
$env:SSDL_PORT = "8877"
.\start.bat
```

接著：

1. 在瀏覽器開啟 `http://127.0.0.1:8877`。
2. 點開 Chrome 擴充功能的視窗，展開「本機連接設定」。
3. 輸入 `8877`，按「連接已登入的 X」。
4. 工具連接頁會顯示實際來源；再次連接時使用保存的連接埠。

擴充功能只接受其自身視窗明確選定的 `127.0.0.1` 目的地；網頁不能靜默修改此設定。連接頁與擴充功能選定的連接埠不一致時，在讀取 Cookie 前拒絕並顯示處理方式。改回 `8765` 時，後端與擴充功能都需要改回。

這個設定不會替服務開啟新連接埠、不掃描電腦上其他服務、不傳送登入資料到遠端伺服器。即使數字合法，已占用的連接埠仍可能無法啟動，需改用空閒的數字。

## 5．驗證範圍

已補齊合成故障測試：API 無回應／內容讀取逾時／壞 JSON／欄位不符／寫入回應遺失、DOM 離線恢復／按鈕／草稿／頁碼／語言切換，以及 Chrome 合成來源／連接埠／加密前置失敗。前輪 Python 59 項、Node 8 項本機通過；後續結果見 [TESTING.md](TESTING.md)。真實 Chrome 自訂連接埠及乾淨 Windows 使用 Python 3.12 的首次安裝驗收仍待執行，進度以 [ROADMAP.md](../ROADMAP.md) 為準。

## 6．停止、保存錯誤與分享診斷

- 下載卡住：先看設定的 worker 狀態；可以按該項目的停止圖示，或等預設 300 秒無進度期限。長影片持續接收資料／合併 CPU 活動不因總耗時被停止。
- 保存錯誤：目前修改只在記憶體，修正磁碟空間／權限後按「重新保存紀錄」，確認狀態恢復再關閉服務。
- 損壞清單：有有效 `data/state.json.bak` 時自動恢復，損壞輸入另存。兩份都無效時不要刪除原檔；先關閉服務並備份整個 `data/`，再處理。
- 較新版本：使用能讀取該 schema 的版本，程式會阻止降版覆寫。
- 回報問題：設定 →「診斷」→「匯出診斷」，檢查內容後再自行分享；不要上傳整個 `data/`、`state.json` 或 Cookie。
- 非公開媒體目標：回環／內網來源、重新導向、串流片段或金鑰會被拒絕。這與正常操作本機網頁不同；需要外部網路下載器的來源也會提示不支援。

具體保存檔案、傳輸限制與驗證範圍見 [可靠性說明](RELIABILITY.md)。
