# 已下載檔案檢查與去重

更新日期：2026-10-11

## 使用者確認的規則

- 一般新增下載時，略過原下載資料夾內、原檔名仍存在且保存紀錄有效的完整檔案。
- 檔案被搬移、刪除、改名，或更換下載資料夾時，重新下載。
- 檢查發生在下次加入網址、重新下載或同步帳號時；目前沒有背景監看資料夾並自動加入工作的功能。
- 檢查原本記錄的位置，不搜尋其他資料夾、不追蹤搬移後的檔案。
- 新保存的媒體使用平台資料夾（例如 `youtube/...`、`twitter/帳號/...`），保存紀錄以下載根目錄下的實際相對路徑核對。整理舊檔案時必須同步更新清單／保存紀錄；使用者自行移動或改名仍按缺檔處理。
- 單篇「重新下載」屬於明確重新取得來源，仍可覆寫；X 帳號項目的箭頭是同步新增及未完成內容。
- `.part` 暫存檔、缺檔、大小不符或無法確認完整的檔案，不視為成功下載。
- 影片畫質偏好也納入一般工作的匹配及來源完成紀錄。最高畫質沿用原紀錄；指定上限例如 720p，另存平台的 `quality-720p` 子資料夾，相同網址的不同偏好不會誤略過或覆寫其他版本。重新下載沿用工作偏好，指定其他畫質請重新提交網址。多媒體貼文中的原尺寸圖片也隨該偏好保存，可能在不同版本資料夾各有一份；圖片直連不受畫質上限影響。

### 一般影片／貼文與通用 manifest

來源完成紀錄涵蓋 yt-dlp、gallery-dl、圖片直連及通用網頁後備下載。完整有效時略過引擎及網路取得；缺檔、改名、搬移或 metadata 改變時重新取得。沒有可信 manifest／舊成功列時不憑同名檔案宣稱完整；資料庫故障也會重新取得並提醒。

YouTube 的 watch／shorts／live／youtu.be 使用相同穩定影片 ID，X 單篇沿用貼文 ID；其他 URL 保留 query。舊成功列來源、原位置及合計大小相符時可匯入，之後逐檔核對大小及修改時間。單檔且穩定 ID、引擎及副檔名不變時可補回舊檔名；相簿或格式改變不只按順序猜測身份。清除工作清單仍保留 manifest 與檔案。

此紀錄不是平台內容變更監控；來源更新時按重新下載。參見 [可靠性與恢復](RELIABILITY.md)。

### 重複列問題與修正（2026-10-10）

使用者回報同一則 X 貼文出現兩筆完成項目。檢查本機紀錄後，這兩筆與更早的一筆都指向相同路徑、相同檔名及相同容量的單一圖片，沒有第二份檔案。舊程式存在兩個問題：新增網址只在同次輸入去重，下一次新增又建立新列；gallery-dl 的略過回呼沿用一般成功處理，因此略過檔案仍顯示「已完成」。舊紀錄沒有保存引擎略過訊號，不能只靠耗時倒推每一次是否傳輸過媒體位元組。

- 同一來源、同一下載資料夾已有完成或失敗項目時，沿用原列，以一般模式重新排隊檢查，不自動強制覆寫。
- X 單篇以貼文編號識別，包含 `x.com`／`twitter.com`、貼文的圖片或影片網址及追蹤參數變體；圖片直連沿用來源指紋，其他網址保留有意義的參數。
- 一般媒體已等待或下載中時，再次加入不重複建立工作。X 帳號已有工作時仍保留既有提示，完成後再次加入則沿用原項目同步。
- gallery-dl 分別記錄實際保存及略過的檔案；全部略過才在本次操作完成時顯示「已略過，檔案已存在」，混合補下載仍顯示完成。yt-dlp 同樣區分已存在檔案與實際下載或合併。
- 重新整理或重新開啟頁面後，歷史項目的徽章顯示「已完成」，滑鼠移上保留上次略過說明。本頁觀察到的本次略過提示不因狀態輪詢或語言切換而清除；不在讀取 API 時修改持久保存結果。
- 再次檢查仍可能解析來源或讀取平台媒體清單；TIME 包含這段處理時間，不能將短時間的完成紀錄視為檔案再次下載。
- 檔案被搬移、刪除、改名或換下載資料夾時，仍按原位置規則取得檔案；單篇明確按「重新下載」仍可強制取得。
- 啟動時合併可確認指向同一組有效檔案的重複完成列，保留最新一列及累計執行次數。合併前備份原清單到 `data/state.before-row-dedup-*.json`；不刪除下載檔案，不回退每小時額度，X 帳號的同步歷史保留。

### 圖片直連

- 成功下載後，保存到 `data/image-history.sqlite3`。紀錄依來源網址指紋與實際下載資料夾分開，不會因另一個位置曾下載過就略過。
- 一般新增會檢查原檔名是否存在，並比較保存時的大小與修改時間；全部相符才略過網路下載。本頁觀察到本次工作完成時顯示「已略過，檔案已存在」，重新整理後顯示「已完成」，仍列在已完成分類。
- 原檔案不存在、大小或修改時間改變時，重新取得來源。紀錄保留原檔名，方便補回原位置；搬移或改名後的那份檔案不會被搜尋或刪除。
- 舊版本的圖片下載可從仍保留的成功清單匯入：同一來源、同一下載資料夾、原檔名存在且大小符合原成功紀錄時，建立新保存紀錄。沒有成功紀錄時會下載，不能只靠同名檔案判斷。
- 按單篇「重新下載」會忽略略過條件，重新取得來源並覆寫同名檔案。來源副檔名改變時可能產生新檔名。
- 無法讀取圖片保存紀錄時會繼續下載並顯示提醒；檔案保存成功但紀錄寫入失敗時也會提醒，下次可能再下載。
- 即使圖片最後略過，一般下載項目的啟動仍依既有規則計入每小時工作額度。

### X 帳號媒體

- 本機紀錄位於 `data/x-profiles.sqlite3`，依帳號、實際下載資料夾及貼文編號分開。
- 每次同步仍須從 X 取得媒體清單；檔名集合、媒體數量及原位置檔案均符合紀錄才略過。新紀錄逐檔比較大小與修改時間；舊紀錄沒有修改時間時沿用大小檢查。
- 帳號同步先掃描完整的本次可存取媒體清單，統計總檔案數、已存在與需要下載數量，再開始取得缺少的媒體。掃描中顯示累計已找到數量；掃描未完成或失敗時不宣稱已知總數，也不開始新的媒體下載。
- 掃描完成後，每篇處理前再次驗證保存紀錄；檔案在掃描期間被搬移、刪除、改名或變更時，更新本次需要下載數量並補抓。額度或平台冷卻的等待結束後也會再核對。完成進度以本次清單內已驗證存在及新保存的檔案數計算，與 Rate 的貼文計數分開。
- 先前以單篇下載的成功項目，只要仍保留在清單、下載位置相同，且檔名與現在的媒體清單相符、檔案容量符合原成功紀錄，即可納入帳號紀錄。完整貼文略過；平台登入後提供更多媒體時可補抓新增部分。
- 貼文只有部分檔案被搬移、刪除、改名或變更時，有逐檔紀錄且仍符合原紀錄的檔案保留，補下載缺少或變更的部分。完成後更新整篇紀錄。
- 舊單篇清單只有合計大小，若其中一個檔案已缺少，就無法確認其餘檔案各自是否完整；這種情況會重新下載該篇媒體。沒有可靠成功紀錄的舊檔案同樣會重新取得。
- 完全略過的貼文不消耗每小時額度；補下載的貼文計一次，多張媒體仍算一篇。
- 清除清單保留 SQLite 保存紀錄及下載檔案，但尚未匯入帳號紀錄的舊單篇項目，清除後就無法再由清單匯入。

### 判斷的限制

目前使用來源識別、原路徑、大小及修改時間作為保存檢查，沒有逐檔內容雜湊。不同來源識別可能保存相同內容；相同來源的上游內容更新需按「重新下載」取得新版。

通用網頁後備解析的直連候選使用「原頁網址＋完整媒體 URL」的網址指紋作為 `web-來源識別`，保留 query，只排除 fragment。不同媒體 ID、畫質或簽章參數保留差異，因此來源更新可能產生新檔名。一般工作先核對來源 manifest；只有有效紀錄才直接略過，沒有可信紀錄時重新取得，避免誤接受同名檔案。候選來源切換不接續先前候選的部分檔案，以免混合不同內容。新版 ID 可能與舊版只使用路徑的 ID 不同，首次使用可能重新取得，舊檔保留。

## 待評估的後續優化

- 評估更多平台的穩定 URL 識別規則，須避免合併不同媒體／畫質。
- 不同網址、不同平台但內容相同的檔案雜湊比較。目前沒有此功能；網址指紋僅識別來源，不代表檔案內容相同。
- 對已清除清單、沒有成功紀錄的舊檔案建立可確認完整性的匯入流程。不能只看到同名檔案就宣稱它完整。

## 檢查方式

後續實測需覆蓋：首次下載、相同來源重加、明確重新下載、多圖貼文部分缺檔、刪除、搬移、改名、更換下載位置，以及清除清單後的同步。此文件不表示上述情境已完成實測。

## Pixiv 作者模式（2026-10-23 來源實作）

2026-10-24 已以 Hoshirapu（82728784）完成 Windows 實際驗收：22 個作品／24 個檔案，再同步 0 重抓；單頁搬離原位置或修改時間後皆只補抓 1 個，其他 23 個不變。停止保留 13 個檔案並繼續補抓其餘 11 個也已觀察。完整紀錄及未驗收範圍見 [Pixiv 驗收](PIXIV_ACCEPTANCE.md)。

Pixiv 作者每次重新掃描，整個作者網址不使用一般完成 manifest 當作永久略過依據。新下載使用 `pixiv/作者名(ID)/`，作者名取自 Pixiv 顯示名稱；單篇作品與作者模式規則一致，作品 ID／頁碼檔名不變。非法路徑字元轉為底線，過長作者名截短，缺少作者名時使用 `Pixiv(ID)`。共用 profiles 資料庫仍以 `pixiv:<author-id>` 與原下載根目錄隔離。新清單需核對同一作者／作品的頁碼檔名與數量，且每頁仍符合已記錄原位置、容量及修改時間才略過。

作者同步會沿用舊數字 ID 資料夾或舊作者名稱下的可信檔案，避免命名規則或作者顯示名稱變更造成重抓；既有資料夾不自動搬移／改名。部分作品可能同時引用舊、新資料夾，缺少的頁面使用新格式。若自行搬移或改名檔案／資料夾，原紀錄核對失敗，仍會重新下載。

成功頁面逐頁保存；部分頁面只供下次核對重用，不能當作完整作品。檔案遺失、改名、搬移、metadata 改變或沒有可信紀錄時重新取得。停止保留檔案；遠端不再列出的舊檔不自動刪除。操作及仍待完成的真實驗收見 [Pixiv](PIXIV.md)。
